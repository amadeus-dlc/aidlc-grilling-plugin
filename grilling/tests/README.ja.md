# grilling テスト

[English](README.md) | 日本語

プラグインルートで `bun install && bun test` を実行します。隣の `aidlc-workflows` checkout（このリポジトリの submodule）からバリデータ・ビルダー・compose フック・コアステージの原文・ハーネスごとの `dist/` install を借ります。checkout が別の場所にあるときは `AIDLC_WORKFLOWS_CHECKOUT` で指定します。ネットワークに出るスイートはありません。opt-in の 2 スイートは環境変数を付けない限り skip されます。

- **`plugin.test.ts` — Authored content** — `aidlc-plugin-validate.ts` が VALID であること。manifest が `overlays` だけを宣言していること。contribution のターゲットが「本文で `-questions.md` に言及するコアステージ」の集合と双方向に一致し、フェーズも合うこと。各 contribution がテンプレートをそのターゲット向けに描画したものと一致し、`sync-contributions.ts --check` も同じ判定を返すこと。各アンカーがコアステージ原文の実在する `### Step N` 見出しに解決すること。テンプレートが label、ラウンド方式の description（0.1.0 の 1 問ずつの description は含まない）、Step 3d、面接が書く固定トークン（`(Recommended)`、`**Mode:** grill`、`**Pending:**`、`Decided assumptions`、段階タグ、`❓` / `➡️`、`X. Other (please specify)`）、Depth の対応表、1 問ずつへの切り替えを含み、150 行以内で、sentinel 風の行や入れ子の fragment 見出しを含まず、フェンスが釣り合っていること
- **`plugin.test.ts` — Harness projections** — 7 ハーネスすべてで `aidlc-plugin-build.ts` が一時ディレクトリへ成功すること。各投影が 28 本の contribution をバイト同一で持ち、compose フックと `aidlc-grilling` という名前のホスト manifest を持ち、`stages/`・`agents/`・`scopes/`・`sensors/`・`tools/`・`knowledge/` を持たないこと
- **`plugin.test.ts` — Compose** — Claude と Kiro について、checkout の `dist/<harness>` install のコピーへ、投影に同梱された本物の `hooks/compose.ts` で compose する。各ターゲットステージがアンカー位置に sentinel で区切られたブロックをちょうど 1 つ持つこと（指定ステップの直後で間に見出しが無い、または直前）。ブロックが `{{HARNESS_DIR}}` 置換済みのテンプレート本文を含むこと。`*.drops` ファイルが書かれていないこと。2 回目の compose で全ステージがバイト同一のままであること
- **`plugin.test.ts` — Shipped gate** — `aidlc-plugin-test.ts . --install <一時 Claude install> --harness claude` が 0 で終了すること（validate、build、compose、グラフ再コンパイル、冪等性、drop 走査）
- **`installer.test.ts`** — 純粋な部分は export された関数で検査する（選択子の排他、安定タグの順序、manifest の検証、tar.gz のパストラバーサル・絶対パス・リンクの拒否、正準なペイロードハッシュ）。次に `bun scripts/install.ts` を、checkout の `dist/claude` の使い捨てコピーに対して `--from <このリポジトリのルート>` で end-to-end に走らせる。不正な引数と取得元は対象に触れる前に拒否されること（選択子の併用、`--update` と選択子の併用・来歴なしの `--update`、不明なハーネス、存在しないプロジェクト、manifest の name 不一致、ツールチェーンの無いプロジェクト）。`--dry-run` は何も書かないこと。本実行で 28 のターゲットステージすべてに断片が入り、5 項目の来歴が原子的に書かれること。2 回目は `Changed 0` でバイト同一であること。`--tag`・`--ref`・latest は意図的に走らせない
- **`release.test.ts`** — git は呼び出しをすべて記録する台本つきのランナー、manifest は mkdtemp 配下のコピー。不安定・不完全・`v` 接頭辞つきの版は git を呼ばずに拒否されること。`main` 以外のブランチ、clean でない作業ツリー、ローカルまたはリモートに既にあるタグは、変更の前に止まること。リリースは manifest を更新し、`add → commit --allow-empty → tag → push --atomic origin main v<version>` の順に呼び、最初の失敗で止まること。`--check-tag` は一致する `v<stable-semver>` を受け付け、不一致・`v` の無い版・プレリリース・name の違う manifest を拒否すること
- **`live-claude.test.ts`**（`AIDLC_CLAUDE_SDK_LIVE=1` または `bun run test:live` で opt-in）— プラグインを `dist/claude` の使い捨てコピーへ compose し、そのコピーの `settings.local.json` で出荷既定の Bedrock を無効化して、`harness/sdk-drive.ts`（フレームワークのテストハーネスからコピー。改変点はファイル冒頭に列挙）で `/aidlc --scope feature …` を Claude Agent SDK 経由で走らせる。SDK の `canUseTool` が本物の `AskUserQuestion` 呼び出しを受け取るので、構造化された選択肢そのものを検証する。メニュー 1 が Guide me / I'll edit the file / Chat / Grill me で説明文が原文どおりであること。Grill me を選んだ後のメニュー 2（最初のラウンド）に 2〜4 問が並び各質問の先頭が `(Recommended)` であること、メニュー 3 は 4 問以下で同じく先頭が推奨であること。質問ファイルに記入済みの `[Answer]:` と `**Mode:** grill` があり、audit shard に 4 択の `DECISION_RECORDED`、Grill me の `QUESTION_ANSWERED`、3 件以上の `DECISION_RECORDED`（画面ごとに 1 件）があること。同じ画面の質問が本当に独立だったかは機械判定せず、人が印字されたメニューを読んで `docs/live-check-<日付>.md` に判断を書く。開発者自身の Claude Code ログイン（`CLAUDE_CONFIG_DIR` を引き継ぐ）と `sonnet` モデル（`GRILLING_LIVE_MODEL` で変更可）を使い、1 回に 5 分程度・数ドルかかる。`AIDLC_KEEP_TEMP=1` で作業領域を残せる
- **`select-plugins.test.ts`**（`GRILLING_SELECT_KEY_CHECK=1` で opt-in）— 選択キー環境の確認。Claude の投影を build し、`dist/claude` を 2 つコピーして、一方の `tools/data/harness.json` に `plugins: ["aidlc", "grilling"]`、もう一方に `["aidlc"]` を書き、本物の `hooks/compose.ts` をそれぞれに走らせる。selected: 終了コード 0、28 ステージすべてに断片がちょうど 1 つ、drop なし、キーは保持。excluded: 終了コード 0、断片はどのステージにも入らず、advisory の drop が `select-plugins` による直し方を示す。結果を `docs/decisions.md` に転記できるよう要約を印字する

`fragment-template.md` は手で編集する唯一のフラグメント本文です。`tests/` は install へ compose されないので、ここに置いています。
